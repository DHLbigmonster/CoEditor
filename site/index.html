三个动作就够了

选中一句话，然后决定它是「要改」「要留」还是「要删」。不需要学编号、批次或提示词。

写批注

在原文上指出哪里要改。正文出现绿色虚线，右侧出现一条意见卡，停手就自动保存。

标记保留

这段写得好、不要动。极淡的暖黄底，不额外划线；Agent 改稿时不得删除或改写它。

提出删除

建议删掉这一句。克制的删除线，正文仍然可读——这是建议，不是真的删掉文件内容。

实例（下面这段就是三种标记的真实样子）：

门店按城市线级分层抽样，写字楼商圈的样本量在此处需要补充口径说明。 样本覆盖 1,208 家门店，季度观测值 3,842 条。 原表 4 的数据与正文不一致，建议整体删除。 其余结论保持原样。

改过之后，要求还在

意见不是聊天记录，是随文档走的资产。关掉窗口、换个会话、隔几周再回来，它们都还在。

已处理的会变灰

这一句已经被改过了，标记变灰但不消失；历史保留，随时能翻回去看当初为什么这么改。

保留是长期的

「保留」不会因为改完一轮就失效。下一轮改稿时，它仍然作为硬约束下发给 Agent。

找不到原文会说清楚

句子被整段替换掉时不乱画线、不假装成功，而是标成「原文已变化」等你确认。

你的文件，继续用原来的格式

跨格式的承诺是统一的批注体验，不是「每种格式都能随便改」。下面是真实边界，不是宣传语。

格式阅读编辑边界
Markdown / TXT支持全文编辑保存有版本锁，外部改过会被拒绝而不是覆盖
HTML原布局，隔离渲染源码 + 就地改字不执行脚本，外链资源默认阻断
JSON / CSV支持支持—
PDF连续页 + 文字层不做 PDF 原文编辑只做批注 / 保留 / 删除建议；扫描件只能框选区域（不做 OCR）
DOCX尽力还原布局文字替换复杂表格 / 页眉脚不保证不变形，未知结构降级处理
PPTX文字模式文字替换完整幻灯片排版预览需要可选的本地组件（LibreOffice），不随包提供、不自动安装
图片原比例—区域批注，坐标按缩放归一化保存

关于 PPT：没装可选组件时，PPT 走文字模式——可以读文字、改文字、批注，但没有逐页排版预览。 我们不假装「PPT 完整支持」。

开始只需打开文件夹

要求 Node.js ≥ 18。不需要 npm install —— 运行时依赖已经随仓库带走。

取到代码 
git clone https://github.com/DHLbigmonster/CoEditor.git
cd CoEditor
指向你的本地文件夹 
node server.mjs ~/Documents
终端会打印一个 127.0.0.1 地址，用浏览器打开即可。
已有 AI 工具？连接一次即可 左下角点「连接 Agent」，把给出的 MCP 配置粘到你的 Agent 里。之后每次改稿， 它都会读到这些批注。
状态灯的含义：连接 Agent（还没接过）→ 等待 Agent 读取（配置已就绪）→ 已连接（确实有 Agent 读过批注）。

别误会：装好 CoEditor 并不会让「任何 AI 自动知道你打开了哪个目录」。 你需要按上面的方式连接一次；不连接也能正常阅读和批注。

常见问题

会把我的文件上传到服务器吗？

不会。本地服务只监听 127.0.0.1，不联网、不上传。批注写在你自己文档目录下的 .marginalia/annotations.json 里。

它内置 AI 吗？

不内置。CoEditor 负责「人在原文上留下要求」，执行改稿的是你自己的 Agent。没有连接 Agent 时，阅读和批注照常可用。

支持哪些 Agent？

通过 MCP 接入。MCP 服务在本地实测过握手与工具列表，但我们还没有在真实宿主的图形界面里端到端点通， 所以不声称「兼容所有 Agent」。接入方式对任何支持 MCP 的客户端都是同一份配置。

PPT 为什么还需要额外组件？

PPT 是二进制版式格式，完整排版还原需要一整套转换器。我们不想把它塞进安装包（体积和信任成本都太高）， 所以做成可选：不装就走文字模式，装了才有逐页排版预览。

能直接改 PDF 吗？

不能，这是有意的。PDF 保持只读，你只能在上面写批注 / 保留 / 删除建议，改动交给 Agent 落到源文件上。

删掉 CoEditor，我的批注还在吗？

在。批注写在文档目录的 sidecar 文件里，不在应用内部。删掉应用不会删掉文档和批注。

不连接 Agent 能用吗？

能。阅读、编辑、批注、保留、历史全部可用；只是这些要求不会被自动带给 Agent。
